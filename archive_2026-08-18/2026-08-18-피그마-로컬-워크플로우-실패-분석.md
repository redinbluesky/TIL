# 2026-08-18-Codext-Figma-Local-Workflow-Failure-Analysis.md
## Context
Claude Plus의 높은 비용을 절감하기 위해, 로컬 Hermes 환경에서 Figma 디자인을 직접 읽어 UI를 생성하려는 시도 중 발생한 문제 분석.

## Problem
1. **비용 문제**: Claude Plus를 통한 Figma-to-Code 워크플로우의 높은 크레딧 소모.
2. **접근성 문제**: 로컬 Hermes는 Figma MCP 서버를 지원하지 않으며, `.fig` 파일을 직접 읽을 수 없음.
3. **데이터 손실**: `.fig` 파일을 zip으로 압축 해제하여 내부 JSON을 직접 읽히는 시도를 했으나, 디자인 요소(레이아웃, 스타일 등)가 제대로 반영되지 않음.

## Root Cause
- **Proprietary Format**: `.fig` 파일은 단순한 압축 파일이 아니라, 복잡한 계층 구조와 바이너리 데이터가 포함된 독자적인 포맷임.
- **Semantic Gap**: 압축 해제된 원시(Raw) JSON 데이터는 디자인의 시각적 의미(Semantic meaning)를 담고 있지 않아, LLM이 이를 UI 코드로 변환하기에는 정보의 밀도와 구조가 부적절함.

## Proposed Solution (The Ladder)
- **Avoid**: `.fig` 파일 직접 압축 해제 및 파싱 시도 (복잡도 과다, 정확도 낮음).
- **Use**: **Figma REST API**를 사용하여 디자인 데이터를 **구조화된 JSON(Design Tokens/Nodes)** 형태로 추출할 것.
- **Workflow**: Figma API $\rightarrow$ Structured JSON $\rightarrow$ `design.md` (System Spec) $\rightarrow$ Hermes/Codex.

## Insight
- "파일을 읽게 하는 것"과 "디자인을 이해시키는 것"은 다르다. 
- 에이전트에게는 파일의 바이너리 데이터가 아니라, **의미가 정제된(Semantic) 명세**가 필요하다.
